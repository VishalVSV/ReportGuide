# How to contribute to this project?

There's two major ways that you can contribute to this project. 

The first way is by opening an issue. You can do so on the issues tab somewhere on top or by [clicking this.](https://github.com/VishalVSV/ReportGuide/issues/new) This is mostly for small issues that can be sorted out by one of the maintainers. Use this for typos or simple grammatical errors.

The second way is a bit more involved but a lot more fun. This is for larger changes to the report guide such as adding a new section. The process is relatively simple. You make a fork of the repository (this should be available on the github website, I am sure there is probably also a way to do this in the cli). You then make any changes you want to your copy or "fork" of the Report Guide. Then you open a pull request. The maintainers of this repository will take a look at your changes and approve it. If you make any significant changes to the Report Guide then please add your name to the acknowledgments at the start of the document.

# Important, regarding the use of LLMs and Generative AI

While there are many valid uses of LLMs and Generative AI, I personally as one of the author's of this document don't think this document is one of them. This project was put on the internet not to be a solution to people but to encourage people to learn how to use git and get used to contributing while sharing their experiences with scientific writing. This document *is not an official or professional* guide. It is written by students and is not guaranteed to improve your reports.

The point of this project is not to produce results. It doesn't matter if there is a faster or better way to do this. The point is to learn something while doing it. We still learn arithmetic even though we have access to calculators. There is meaning to learning and doing things by hand. Not everything needs to be done "efficiently".

As such this project will not accept any contributions written entirely or significantly by AI. The use of AI in writing LaTeX code is acceptable but you could honestly spend that time learning LaTeX and it would serve you better in the long run. Any content written by AI will also be rejected on similar grounds. This extends to figures and other media. If you disagree with this policy that is completely fine. You are free to open a fork and run it the way you want :), in fact I would encourage it.
